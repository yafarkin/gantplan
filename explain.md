# GantPlan — краткое описание проекта

## Что это
Планировщик проектов (Gantt-планирование) на C#/.NET 8, который автоматически
расставляет задачи по датам и исполнителям, решая задачу как
constraint-programming модель через Google OR-Tools (CP-SAT).

Проект — это не просто визуализация диаграммы Ганта, а **солвер**: на входе
дерево задач с ограничениями (длительность/оценка, зависимости, приоритеты,
дедлайны, доступные исполнители), на выходе — рассчитанные start/end по
каждой задаче и назначенный исполнитель, с учётом календарей (выходные,
отпуска, недоступность ресурсов).

## Структура решения (GantPlan.sln)
- **GantSolver** — библиотека с доменными моделями (Dtos), логикой солвера
  (Logic) и подготовкой данных для визуализации + HTML-шаблон дерева задач
  (Visualize, Templates).
- **Planner** — консольное приложение-точка входа: читает `project.json`
  (либо берёт демо-проект из `SourcePlans/DemoProject.cs`), прогоняет солвер,
  сохраняет результат обратно в `project.json` и генерирует `timeline.html`
  (открывает его в Finder/проводнике).
- **Tests** — юнит-тесты (NUnit), по темам: солвер (SolverTests — базовое
  планирование, SolverCalendarTests — календари, SolverFactTests — план/факт),
  разворот дерева (TaskAlignmentTests), валидация (ProjectValidatorTests),
  календарь, отчёты и таймлайн.

Общие настройки сборки — в `Directory.Build.props` (в т.ч.
`TreatWarningsAsErrors`: любое предупреждение компилятора ломает сборку),
стиль кода — в `.editorconfig`.

## Доменная модель (GantSolver/Dtos)
- `ProjectDto` — дата старта проекта, дата среза "на сегодня" (`FactDate`),
  корневая задача (дерево), список ресурсов, глобальный календарь.
- `TaskDto` — задача (может быть контейнером с `Children` или листовой), с
  `Limit` (ограничения планирования), `Plan` (расчётный план: исполнитель,
  даты) и `Fact` (фактический прогресс).
- `TaskLimitDto` — приоритет, длительность (число дней **или** t-shirt размер
  XS..XL), буфер на неопределённость, требуемая роль или конкретный
  исполнитель, список предшественников (FS-зависимости), DueDate/StartAfter.
- `ResourceDto` — исполнитель: роль, имя, окно доступности (AvailFrom/To),
  загрузка в процентах (Percent), персональный календарь, Confidence (для
  перевода t-shirt размера в дни).
- `TaskFactDto`/`TaskFactRecordDto` — журнал фактических событий по задаче
  (Started/InProgress/Completed/Canceled/Paused/ChangedAssignee/
  CorrectedDuration) — используется для перепланирования "недоделанного"
  проекта с учётом того, что уже произошло по факту.
- `CalendarDto`/`CalendarPeriod` — списки нерабочих/рабочих периодов
  (глобальные и персональные, с приоритетом персональных).

## Солвер (GantSolver/Logic)
- **TaskAlignment** — тонкий оркестратор, разворачивающий дерево задач в
  плоские списки для Solver'а. Сама логика разнесена по классам с одной
  ответственностью на каждый:
  - **TaskTreeIndex** — индексирует дерево по id (без копирования задач):
    все узлы, только листья, и разворот любого id (лист или группа) в id
    его листьев — так "задача зависит от группы задач" резолвится в
    "зависит от всех листьев внутри группы" без отдельного спецкейса в коде.
  - **TaskAttributeInheritance** — наследует вниз по дереву то, что не
    задано у ребёнка явно: произвольные теги (`TaskDto.Tags`, например
    WorkType/IsOkr — не участвуют в ограничениях солвера, нужны только для
    статистики), `Limit.Priority` и `Disabled`.
  - **ProjectValidator** — проверяет бизнес-правила, от которых зависит
    Solver (Limit есть, приоритет известен, исполнитель резолвится,
    предшественники существуют, нет циклов), и собирает все найденные
    проблемы в один список вместо падения на первой же.
  - **LeafTaskCopier** — делает solver-безопасные копии листовых задач.
  - **PredecessorResolver** — переписывает `PredecessorIds` копий,
    разворачивая групповые зависимости и выбрасывая уже
    завершённых/выключенных предшественников.
- **CalendarLogic** — строит булев массив рабочих/нерабочих дней на горизонте
  планирования, объединяя календарь выходных, глобальный календарь проекта
  и персональный календарь ресурса; умеет считать число рабочих дней между
  двумя датами и день окончания задачи по старту и числу рабочих дней.
  Тот же календарь использует и таймлайн, так что диаграмма не расходится
  с планом.
- **Solver** — ядро:
  - Сначала строит простой жадный план (задачи по готовности, приоритету и
    порядку в дереве, каждая — исполнителю, у которого раньше закончится).
    Его срок с запасом (+25%, не меньше 14 дней) — горизонт планирования,
    а сам план — подсказка солверу, чтобы у того сразу было допустимое
    решение. Горизонт не зашит: проект любой длины (до ~10 лет) решается.
  - Строит CP-SAT модель: переменные start/end (в днях от старта проекта) на
    каждую задачу.
  - Зависимости между задачами (finish-to-start), ограничения DueDate/StartAfter.
  - Для каждой задачи перебирает кандидатов-исполнителей (конкретный
    ресурс/роль/тот, кто уже делал задачу в реальности) и создаёт опциональные
    интервалы — активен только интервал выбранного ресурса (`AddExactlyOne`).
  - Переводит бизнес-дни в календарные по календарю ресурса: для каждого
    возможного старта день окончания посчитан заранее, связь задаётся одним
    `AddElement`. Старт и окончание в нерабочий день запрещены.
  - Учитывает недоступность ресурса (AvailFrom/AvailTo, оба включительно)
    как "занятые" интервалы и не даёт задачам пересекаться у одного
    исполнителя (`AddNoOverlap`).
  - Уже начатая задача (`Fact.IsProgress`) фиксирована: старт — из последней
    записи факта, исполнитель — тот, кто её делал, длительность — остаток.
  - Целевая функция: минимизировать makespan (срок всего проекта) + штраф за
    поздний старт высокоприоритетных задач (веса по Priority 1/2/3).
    Приоритет — сильное пожелание, а не жёсткий порядок; жёсткий порядок
    задаётся через `PredecessorIds`.
  - Если оптимум доказан, второй этап выбирает среди планов с той же целью
    однозначный: раньше стартуют задачи, стоящие раньше в дереве, первому
    исполнителю из списка — первая задача. Без этого равноценные задачи
    могли меняться местами от прогона к прогону.
  - Статус решения (Optimal/Feasible/Infeasible/Unknown), цель, горизонт и
    время выводятся в консоль (`Planner`).
  - После решения (`PostFillAfterSolve`) переводит результат в даты,
    определяет фактического исполнителя, дописывает Fact-записи о ходе
    выполнения на основе `FactDate` (если задача уже должна была
    начаться/закончиться/быть в процессе на дату среза), агрегирует план
    родительских (составных) задач снизу вверх.

## Визуализация
`TaskTreeDataPreparer` строит дерево задач как есть (с уже посчитанными
датами, статусами, исполнителями, ссылками на Jira) и подставляет его в
HTML-шаблон (`Templates/task_tree_template.html`) — самодостаточная страница
на D3, открывающаяся в браузере/проводнике после расчёта. По умолчанию
открывается диаграмма Ганта по исполнителям (трек на человека, пересекающиеся
по датам задачи разносятся по дорожкам); разворачивание трека показывает
дерево эпиков/задач этого человека, второй режим - "по задачам" - дерево
целиком.

d3 встраивается прямо в страницу (`Templates/d3.v7.9.0.min.js`), поэтому
`timeline.html` открывается с диска и без интернета. Нерабочие дни
(выходные, праздники, рабочие переносы, отпуска и личные рабочие дни)
приходят из того же `CalendarLogic`, что и у солвера; дата среза
(`FactDate`) подсвечена колонкой "сегодня".

## Зачем это нужно
Автоматизировать составление и **перепланирование** календарного плана
команды: не вручную двигать бары в Ганте, а описать задачи/оценки/зависимости/
приоритеты и доступность людей — и получить оптимальный (по срокам и
приоритетам) план с учётом уже сделанного факта. Поддерживает T-shirt-оценки
с доверительным интервалом, буферы на неопределённость, частичную занятость
ресурсов, персональные и общие календари отпусков/праздников.

## Стек
.NET 8, Google.OrTools (CP-SAT solver), Mapster (маппинг/копирование DTO),
Newtonsoft.Json (сериализация project.json).
