3. **`CalendarLogic` крашится на пересекающихся ГЛОБАЛЬНЫХ периодах, но не
   на персональных.** `GantSolver/Logic/CalendarLogic.cs:29,38` vs `:47,56`:
   для `globalCalendar` используется `.SingleOrDefault(...)` (бросит
   `InvalidOperationException`, если два периода в `NonWorkingDays`/
   `WorkingDays` перекрываются на одну дату), а для `resourceCalendar` —
   `.FirstOrDefault(...)` (спокойно берёт первый). Реалистичный сценарий:
   общий календарь праздников собран из двух источников (гос. праздники +
   компания), даты пересеклись — весь `Solve()` падает необработанным
   исключением на ровном месте.

4. ✅ **Сделано.** `StartAfterTest` содержал подавленный, не разобранный
   баг → разобрано: тест написан в сентябре 2025, до фикса "Fixed bug with
   non-working days constraints stretching task duration" (`12ca9b9`,
   август 2026) — это и есть тот самый "иногда очень длинная последняя
   задача". Проверил напрямую: с ОТКАТАННЫМ фиксом тест реально вычисляет
   `09.01.2026` (старое ожидание), с фиксом — `05.01.2026`, что и есть
   математически верный ответ (S = 3 рабочих дня от четверга 01.01 через
   выходные). Тест раскомментирован с правильным значением.

5. **`DueDate` vs уже начатая (`Fact.IsProgress`) задача — ноль тестов,
   ноль объяснения при провале.** Если задача уже в работе, её старт и
   длительность в модели становятся жёсткой константой
   (`Solver.cs:339-354`); если это делает недостижимым `DueDate`, модель
   становится infeasible, `Solve()` вернёт `false` неотличимо от любой
   другой причины провала.

6. **`ResourceDto.Percent` без валидации диапазона.**
   `Solver.cs:570-573`: `duration * 100.0 / resource.Percent`. При
   `Percent == 0` — `Convert.ToInt32(double.PositiveInfinity)` бросает
   необработанный `OverflowException`, роняя весь прогон с непонятным
   сообщением вместо человеческой ошибки валидации. Отрицательный `Percent`
   не падает, но тихо даёт бессмысленную 1-дневную длительность. Ни одного
   теста на `Percent` нет вообще.
